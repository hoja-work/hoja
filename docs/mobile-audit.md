## Lint (`npm run lint:ui`, `npm run lint:styles`)

ESLint runs on `frontend/src` with `eslint-plugin-jsx-a11y` and `eslint-plugin-react-hooks` (`frontend/eslint.config.mjs`).
It currently reports zero errors. Stylelint runs the CSS rules (`npm run lint:styles`).

Rules enforced:
- `jsx-a11y/control-has-associated-label`: buttons and links need a name. Form fields are covered by `label-has-associated-control`.
- `jsx-a11y/click-events-have-key-events`, `no-static-element-interactions`, `interactive-supports-focus`: pointer-only handlers need a keyboard path or an explicit non-interactive role.
- `jsx-a11y/no-autofocus` (DOM elements only): autofocus opens the phone keyboard unprompted.
- `react-hooks/rules-of-hooks`, `react-hooks/exhaustive-deps`.
- Stylelint: `clinear/no-viewport-height-units`, `clinear/no-small-field-font`.
- Runtime gate: `npm --prefix frontend run test:mobile` (touch targets, overlaps, unlabeled controls, field font, overflow, at 390px and 320px).

Suppressions still in the code (each has a reason in its comment):
- `main.tsx`: six route- and session-driven effects in `App` (issue load, project load, notification load, notification version, issue drawer, sync session). Each either writes the state it reads, or is recreated on every render, so adding it to the dependency list would loop or refetch. Fixing these needs the effects moved into the stores they belong to.
- `linear/shared.tsx` `LabelChip`: the `role` depends on whether `onClick` is passed.
- `AgentChatPage.tsx`: the history panel closes on a delegated click. The thread buttons inside it are the keyboard path.

## List-row behavior (scripts/mobile-row-check.cjs)

Each row is matched by its identity, not by position, because lists reorder on reload. The check passes only when the row opens the thing it names.

Covered at 390px:
- Issue rows (My issues Assigned and Created, Board, team issue list): `opens-named-issue`. The URL must be that issue's identifier, optionally followed by a title slug. 12 rows in the seeded run; 42 in the scale run.
- Project rows (Projects, and the Pulse project links): `opens-named-project`. The URL must be a project route and the page must name that project. 11 rows.
- Pulse comments toggle: `opens-comments`. The control's `aria-expanded` must be `true` after the click.
- Cycle rows (team current cycles): `opens-named-cycle`. The URL must be a cycle route and the page must contain that cycle's region label. 3 rows.

The seeded run needs a cycle cadence and one pulse post, which the scale seed does not create. Reproduce with `teamCycleCadenceEnable(teamId, weekday: 1)` on the ENG team and `projectUpdateCreate(projectId, body, status: "onTrack")`.

## Behavior fixes found in the review (this pass)

- Dead controls: the click-through found controls that did nothing. `local/no-dead-button` now flags any `<button>` or `IconBtn` with no handler, no `disabled`, and no submit type. It found three real ones, fixed as follows:
  - Sub-issue display settings (issue detail): no handler. Now disabled with a reason.
  - Create issue in <group> (cycle groups): no handler. Now disabled with a reason.
  - Open issue title button (My issues): relied on the row's click handler. Now has its own handler.
- Native dialogs: `window.confirm`, `window.prompt`, and `window.alert` are unstyled and block the page. `local/no-native-dialog` now forbids them. The 12 call sites use `confirmDialog`, `promptDialog` and `alertDialog` from `src/dialogs.tsx`, mounted once at the app root. Verified: deleting a label opens the in-app Cancel/Confirm dialog, and Confirm deletes it.
- Behavior check for no-effect controls: most of the 46 are expected. Tabs already selected; copy buttons (clipboard, no DOM change); external documentation link (new tab); New chat on an empty thread. Found by testing: Create member opens a form, Favorites toggles its label. The click-through misses label-only and new-tab changes, so `no-effect` is an upper bound, not a list of bugs.
