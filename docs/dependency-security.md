# Dependency security policy

Warnings are treated as a build failure, not as ambient noise. Three surfaces
are audited separately because they fail in different ways:

| Surface | Checked by | Fails on |
| --- | --- | --- |
| `frontend/` npm tree | `npm audit --audit-level=high` | high, critical |
| Python lock (`uv.lock`) | `pip-audit -r` on `uv export` | any known advisory |
| Container base images | `docker compose build --pull` on deploy | stale base layers |

CI runs the first two on every push and pull request, plus a weekly schedule
(`.github/workflows/security-audit.yml`); Dependabot opens grouped patch/minor
PRs for npm, pip, Docker and GitHub Actions (`.github/dependabot.yml`).

## The deploy path is part of this

A container image freezes its dependencies at build time, so an audited source
tree can still ship a stale base layer. `scripts/deploy-hoja.sh` builds with
`docker compose build --pull`, and the image upgrades `pip` before installing
the project — `pip` 25.0.1 carried 12 advisories in the live image on 2026-11-03
even though every application dependency was clean.

## How to run the checks by hand

```bash
# npm
cd frontend && npm ci && npm audit --audit-level=high

# Python (uses the lock, not the ambient environment)
uv export --frozen --no-emit-project --format requirements-txt -o /tmp/req.txt
uvx pip-audit -r /tmp/req.txt

# the server itself, not the lock
ssh root@45.32.168.82 'docker exec hoja-app python -m pip list --format=freeze' \
  > /tmp/server-freeze.txt
uvx pip-audit -r /tmp/server-freeze.txt
```

The last command needs the local packages (`hoja`,
`google-workspace-connector`) removed from the freeze list first: they are not
on PyPI, and `pip-audit` aborts instead of skipping them.

## Accepted, with reasons (measured 2026-11-03)

`npm audit` reports **0 high, 0 critical**. The remainder is real but bounded:

- **12 moderate, all inside the ESLint toolchain** (`minimatch`,
  `@eslint-community/eslint-utils`, `@eslint/*`). Dev-only: none of it is in
  the bundle or the image. The upstream fix is ESLint 10, and ESLint 10 is not
  adoptable yet — `eslint-plugin-jsx-a11y@6.10.2` declares
  `eslint: ^3 || … || ^9`, so `npm ls` reports the peer as invalid and the
  plugin ecosystem has not caught up. Upgrading anyway was tried on 2026-11-03:
  it surfaced 12 pre-existing `jsx-a11y` errors (since fixed in
  `src/linear/issues.tsx` and `src/main.tsx`), and the peer conflict remained.
  Revisit when `eslint-plugin-jsx-a11y` supports ESLint 10.
- **5 low, KaTeX chain** (`katex`, `rehype-katex`, `remark-math`,
  `micromark-extension-math`), pulled by `@openuidev/react-ui`. Only rendered
  for math in agent-chat markdown; no untrusted math input path today.

Everything above is regenerated by the weekly job, so an accepted item that
gets a fixed upstream version shows up as a Dependabot PR rather than being
forgotten.
